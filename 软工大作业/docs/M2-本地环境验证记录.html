4.2 本轮踩到并解决的三个坑

坑 1：MySQL 的 root 密码不是项目默认的 root。 application-center.yml 第 11 行写的是 ${ONEBLOG_DATASOURCE_PASSWORD:root}，默认值 root 与本机实际密码不符，直接启动会认证失败。处理方式：用环境变量覆盖，不改文件、不把密码写进仓库：

set ONEBLOG_DATASOURCE_PASSWORD=<本地 root 密码>

坑 2：Redis 未安装，且 GitHub Release 下载被拦。 本机无 redis 进程、6379 无监听；curl 直连 GitHub Release 报 schannel: server closed abruptly，winget install Redis.Redis 报 InternetOpenUrl() failed 0x80072efd。处理方式：经镜像 ghfast.top 下载 Redis-x64-5.0.14.1.zip（12.6 MB），解压到 D:\Redis，用 redis.windows.conf 启动（bind 127.0.0.1、port 6379、无密码），redis-cli ping 返回 PONG。 注意：启动参数 --maxheap 512mb 在 5.x 上不合法，会报 unknown argument: maxheap，不要加。

坑 3：端口被环境变量覆盖成 62781。 首次启动报 PortInUseException: Port 62781 is already in use，而 application.yml 里写的是 8443。原因是本机存在环境变量 SERVER__PORT=62781，Spring Boot 的宽松绑定把 SERVER__PORT 映射为 server.port，优先级高于 yml。处理方式：启动时显式指定，如 set SERVER__PORT=8443。 这条是本轮最容易被误判成「代码有问题」的坑：日志里没有数据库或模板错误，只有一句端口占用。

5 可复现方式

仓库新增两个脚本，避免每次手敲环境变量：

脚本 作用
scripts/dev-start.bat 检查并拉起 Redis → 检查 jar → 交互输入数据库密码（不回显、不落盘）→ 分别以 8443 / 8085 启动前台与后台
scripts/dev-stop.bat 按端口找到 PID 并停止 8443 / 8085 上的进程（不动 Redis）

首次使用前需先执行一次 mvn clean package -Dmaven.test.skip=true。
